12// Convenience foundational driver for display devices that use the common
13// concept of 'address window'. Virtually all SPI devices, including various ILI
14// and ST devices, belong in this category. This class implements the entire
15// contract of a display device, providing an optimized implementation for pixel
16// write, using a Compactor class that detects writes to adjacent pixels and
17// minimizes the number of address window commands.
18//
19// To implement a driver for a particular device on the basis of this class, you
20// need to provide an implementation of the 'Target' class, with the following
21// template contract:
22//
23// class Target {
24// public:
25// typedef ColorMode;
26// static constexpr ByteOrder byte_order;
27// Target();
28// Target(Target&&);
29// Target(int16_t width, int16_t height);
30// int16_t width() const;
31// int16_t height() const;
32// void init();
33// void begin();
34// void end();
35// void setOrientation(Orientation);
36// void setAddrWindow(uint16_t x0, uint16_t y0, uint16_t x1, uint16_t y1);
37// void ramWrite(raw_color* data, size_t size);
38// void ramFill(raw_color data, size_t count);
39//};
40//
41// See ili9341.h for a specific example.
42//
43// Many display devices rely on the same underying hardware contract, assumimg
44// that the display is connected to some kind of shared bus (e.g. SPI), and that
45// it has dedicated pins for 'chip select' (CS), 'data / command' (DC), and
46// optionally reset (RST). If your device fits this description, you can use
47// TransportBus (see transport_bus.h) to implement the Target.
