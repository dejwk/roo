12// Images are drawables that render a rectangular area based on data from some
13// underlying immutable data source. Image classes are templated on Resource,
14// which specifies the source of input data, such as DRAM memory, flash memory,
15// or SD card. Specific Resource classes are included in the io/ subdictory; you
16// could also roll your own based on those.
17//
18// Each image class recognizes a particular image data format, such as
19// raster bitmap, or RLE-encoded image data.
20//
21// Images do not have a common base class. Every image can be used as a
22// Drawable; many are Streamable (see core/streamable.h), and some might be
23// Rasterizable (see core/rasterizable.h).
24
25// Streamable and Rasterizable images can be super-imposed (and alpha-blended)
26// over each other, and over other Streamables, without needing to store the
27// entire content in DRAM. A common use case is to super-impose semi-transparent
28// images over solid backgrounds. For example, you can define a button with a
29// single image label, and varying background color depending on button state.
30//
31// Note: for simple raster (uncompressed) images, stored in native ColorMode
32// formats, use Raster from core/raster.h.
33//
34// How to implement a new Streamable image class:
35// 1. Implement a new 'stream' type, with methods Color next() and skip(int),
36// that will return pixels of your image from the top-left corner
37// 2. In a typical case when your image is rendering the entire stream
38// and is backed by a memory pointer, it generally suffices to typedef
39// it as SimpleStreamable<YourStreamType>
40// 3. If the image represents a clipped sub-rectangle of the stream, use
41// ClippedStreamable instead of SimpleStreamable.
42// 4. If you need a more customized constructor, inherit rather than
43// typedef, and delegate your constructor. See XBitmap, below.
