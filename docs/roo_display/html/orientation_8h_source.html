8// Represents an orientation of a display device.
9//
10// A display device is assumed to have a 'natural' physical placement,
11// determining in absolute terms which way is 'up', 'down', 'left', and 'right'.
12// Orientation (represented by this class) clarifies how the logical (x, y)
13// coordinates are mapped to those physical directions. For example:
14// * RightDown: the x coordinate goes left-to-right, and the y coordinate goes
15// top-to-bottom. This is a 'default' orientation.
16// * UpRight: the x coordinate goes bottom-to-up, and y goes left to right
17// * etc.
18//
19// Internally, orientation is represented as a single byte value. The
20// orientation should be passed by value.
21//
22// Orientation can effectively take one of 8 values, which can be thought of as
23// either:
24// * 4x 90-degree rotations, each optionally mirror-flipped
25// * 3 independent binary parameters:
26// * whether the horizontal dimension corresponds to x or y,
27// * whether the horixontal axis is left-to-right vs right-to-left,
28// * whether the vertical axis is top-to-bottom vs bottom-to-top.
29//
30// Helper methods are provided to transform (re-orient) orientations.
31class Orientation {
32 public:
33 enum HorizontalDirection { LEFT_TO_RIGHT = 0, RIGHT_TO_LEFT = 1 };
34
35 enum VerticalDirection { TOP_TO_BOTTOM = 0, BOTTOM_TO_TOP = 1 };

52 // Returns an orientation that results from taking a default orientation
53 // (RightDown) and rotating it clockwise by 90 degree 'count' times. If count
54 // is negative, the rotation is effectively counter-clockwise by abs(count).
55 // Rotations with the same value of count % 4 are effectively equivalent.
56 static Orientation RotatedByCount(int count) {
